# RAG-система по правилам фигурного катания

### 1. Архитектура пайплайна

#### 1.1 Общая схема

```
PDF / Web (ISU)
        ↓
Загрузка данных (pdfloader, webloader)
        ↓
Очистка текста + извлечение таблиц
        ↓
Инференс метаданных
(audience, discipline, level, doc_type, season)
        ↓
Chunking документов
(RecursiveCharacterTextSplitter)
        ↓
Векторизация
(BAAI/bge-m3)
        ↓
FAISS (cosine similarity)
        ↓
Retriever (top_k, metadata filter)
        ↓
LLM + Prompt
```

#### 1.2 Взаимодействие компонентов

* **pdfloader.py**

  * Извлекает текст и таблицы из PDF
  * Объединяет многостраничные таблицы
  * Приводит таблицы к структурированному виду (JSON + markdown)
  * Очищает PDF-текст от шумов
  * Инферит метаданные документа (аудитория, дисциплина, тип документа и др.)

* **webloader.py**

  * Загружает правила ISU с официального сайта
  * Устраняет артефакты склейки слов

* **Chunking**

  * Деление документов на чанки фиксированного размера
  * Используются размеры: 2000 / 2700 / 3500 символов

* **Embedding слой**

  * Мультиязычная модель `BAAI/bge-m3`
  * Поддержка русского и английского языков

* **FAISS**

  * Хранение эмбеддингов
  * Поиск по cosine similarity

* **Retriever**

  * similarity_search с фиксированным `top_k`
  * Опциональная фильтрация по метаданным

---

### 2. Реализация основной логики (RAG)

* **Векторизация**: документы → чанки → эмбеддинги
* **Векторная база**: FAISS индексы для разных размеров чанков
* **Retrieval**:

  * `top_k = 100`
  * baseline: поиск без фильтрации по метаданным
  * расширение: retrieval с фильтрацией по метаданным

---

### 3. Первичное тестирование качества

#### 3.1 Валидационная выборка

Сформирована выборка из **100 вопросов**:

* 50 — сгенерированы LLM
* 50 — составлены вручную

Вопросы разнообразны:

* по дисциплинам (singles / pairs / ice dance / synchro)
* по аудитории (ISU / профессионалы / любители)
* с орфографическими и логическими ошибками
* с шумом (разговорная форма, опечатки)

Дополнительно:

* созданы версии с ошибками - опечатками и логическими ошибками (как пример, выброс в одиночном катаении)

Данные хранятся в **Google Sheets** со следующими полями:

* Вид катания
* Проф / не проф
* Pdf_name (ожидаемый источник)
* Логическая ошибка в вопросе (если есть)
* Количество вопросов в запросе
* Текст запроса
* Ожидаемый ответ
* Ответ системы

---

#### 3.2 Логика тестирования retriever

Зафиксировано:

* `top_k = 100`

Для каждого вопроса:

1. Выполняется retrieval
2. Анализируются **Top-10 чанков** из top_k

##### Вариант 1 — ручная разметка

* Для каждого чанка в Top-10 проставляется:

  * `1` — релевантен вопросу
  * `0` — нерелевантен

##### Вариант 2 — LLM as a Judge

* LLM получает:

  * вопрос
  * текст чанка
* Возвращает:

  * бинарную оценку `0 / 1`
  * краткое пояснение релевантности
  * confidence score

После разметки:

* чанки с низким confidence проверяются вручную
* чанки с некачественным пояснением дополнительно анализируются


### 4. Baseline-решение

Baseline конфигурация:

* FAISS + `BAAI/bge-m3`
* chunk_size = 2700
* overlap = 600
* similarity_search без metadata-фильтрации
